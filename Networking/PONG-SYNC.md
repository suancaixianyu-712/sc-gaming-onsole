# 双人联机乒乓同步（1.4.0）

游戏标识为 `pong-online`。房间容量必须为 2，`requiresUdp = true`。后端启动时注册 `PongRoomHandler`，每局创建独立的服务器模拟；AI 乒乓和打砖块仍使用本地逻辑。

## 连接和对局流程

1. 运行后端，默认监听 TCP 26051 / UDP 26052。
2. 在 PSP 首页选择“乒乓对决 → 开始游戏 → 双人 / 联机对战”。
3. 两人输入同一个服务器地址并连接，一人创建房间，另一人输入 6 位房间码加入。
4. 双方准备且 UDP 就绪后，房主开局。服务器分配新的 `matchId`，发出可靠初始状态。
5. 倒计时 3 秒后自动发球；首球随机选择朝向和轻微左右偏移，之后朝得分的一方发球。
6. 得分后显示新比分，间隔 1.2 秒自动发球，先到 5 分结束。服务器先通过 TCP 发出最终结果，再结束对局并清除双方准备状态。
7. 结算页 X 或 O 返回房间，双方重新准备后可再次开局。

比赛中 O 离开房间会结束本局，另一方回到房间；HOME 或关闭 PSP 断开连接。START 只提示联机比赛不能单人暂停。打开所有 PSP 页面时，世界人物的移动、视角和物品操作仍被屏蔽。

## 同步职责

| 内容 | 实现 |
| --- | --- |
| 游戏规则 | 服务器决定球、反弹、得分、倒计时和胜负，客户端只发送左右方向轴 |
| 模拟 | 固定 60 Hz，每步 4 次物理细分，球/挡板碰撞计算为 240 Hz |
| 输入 | 客户端固定 60 Hz，方向轴量化为有符号 16 位整数，附带输入序号 |
| 状态 | UDP 30 Hz 整帧快照，包括挡板、球、速度、比分、阶段和已处理输入序号 |
| 可靠事件 | TCP 初始状态、阶段变化（含得分）、最终结果；房间和准备操作也走 TCP |
| 自己的挡板 | 本地立即预测，收到快照后从服务器位置重放尚未确认的输入 |
| 预测修正 | 小于等于 32 像素的差异平滑收敛，较大差异直接校正；位置始终受场地边界限制 |
| 球与对手 | 按服务器 tick 缓冲约 75 ms，插值显示；球最多外推 50 ms，之后停留等待新状态 |
| 丢包 | UDP 仅保留最新输入/快照；服务器持续使用最近方向轴，超过 250 ms 未收到输入则停住该挡板 |
| 等待同步 | 超过 500 ms 无新快照、超过 30 步输入未确认或 UDP 断开时显示提示，服务器继续裁决 |

客户端不会模拟球与挡板的碰撞，也不会自行增加比分。球在有限外推期间可按墙面反射显示；该显示结果不会提交给服务器。阶段或回合变化会清空球的插值缓存和拖尾，防止把上一回合与新发球连接起来。

服务器处理输入时校验玩家身份、当前房间、`matchId`、序号和方向范围。客户端只能影响自己挡板的方向，不能传入球位置、挡板绝对位置或比分。TCP 和 UDP 到达次序不同，客户端按快照 tick 丢弃旧状态；跨局数据按 `matchId` 丢弃。

## 双方视角

服务器坐标场地为 960 × 540，座位顺序靠前的玩家控制下方挡板，另一位控制上方挡板。

第二位玩家的显示坐标旋转 180°：`x' = 960 - x`，`y' = 540 - y`。他的本地方向输入在服务器中取反。这样两人都操作屏幕下方的挡板，按本地“左”始终向自己的左边移动，比分左侧始终是自己的分数。

上下挡板矩形起点分别为 y=91 和 y=437，厚度 12，形成对称场地；宽度 140，速度 640 像素/秒。目标线 y=58 / y=482，球半径 8，初始速度 330，每次接球增加 9，上限 550。接球位置决定反弹角度。

## 操作码

负载版本均为 1，整数和浮点数均使用小端格式。实时数据外层使用通用 UDP 帧；TCP 负载存放在 `game_message.payload`，以 JSON byte[] 的 Base64 形式传输。

| 操作码 | 通道 | 方向 | 内容 |
| --- | --- | --- | --- |
| 1 | UDP | 客户端 → 服务器 | 7 字节完整方向输入 |
| 2 | UDP | 服务器 → 客户端 | 52 字节状态快照 |
| 100 | TCP | 服务器 → 客户端 | 初始状态，52 字节 |
| 101 | TCP | 服务器 → 客户端 | 阶段变化或得分后的状态，52 字节 |
| 102 | TCP | 服务器 → 客户端 | 最终结果，52 字节，phase=Finished |

服务器消息的 `senderId` / `playerId` 为 `Guid.Empty`，实时服务器状态使用 LiteNetLib channel 8。玩家输入使用 channel 0。输入负载中的序号用于预测确认，独立于 UDP 外层的传输序号。

### 输入负载（7 字节）

| 偏移 | 长度 | 类型 | 内容 |
| --- | --- | --- | --- |
| 0 | 1 | byte | 负载版本，1 |
| 1 | 4 | UInt32 | 本局输入序号，按 60 Hz 递增 |
| 5 | 2 | Int16 | 本地方向轴，-32767 到 32767；0 停止 |

方向轴除以 32767 得到 -1 到 1，支持摇杆模拟量；方向键发送 -1、0、1。旧输入被忽略，UInt32 序号按有符号差值比较以支持环回。输入包不携带客户端位置或可信时间。

### 状态负载（52 字节）

| 偏移 | 长度 | 类型 | 内容 |
| --- | --- | --- | --- |
| 0 | 1 | byte | 负载版本，1 |
| 1 | 1 | byte | 阶段：0 Countdown、1 Playing、2 PointDelay、3 Finished |
| 2 | 1 | byte | 下方玩家比分 |
| 3 | 1 | byte | 上方玩家比分 |
| 4 | 4 | UInt32 | 服务器模拟 tick |
| 8 | 4 | UInt32 | 回合号，每次得分递增 |
| 12 | 4 | UInt32 | 下方玩家最近已处理的输入序号 |
| 16 | 4 | UInt32 | 上方玩家最近已处理的输入序号 |
| 20 | 4 | Single | 下方挡板中心 x |
| 24 | 4 | Single | 上方挡板中心 x |
| 28 | 4 | Single | 球 x |
| 32 | 4 | Single | 球 y |
| 36 | 4 | Single | 球速度 x |
| 40 | 4 | Single | 球速度 y |
| 44 | 4 | Single | 倒计时或回合间隔剩余秒数 |
| 48 | 4 | UInt32 | 当前回合接球次数 |

开局时两人挡板和球居中，比分为 0。Finished 状态中的比分直接确定胜负；结果不写入单人 AI 胜场或单人奖杯。

## 断线和实现范围

- UDP 临时断开保留房间，客户端自动尝试重新绑定；输入超时的挡板停止，比赛仍继续。
- TCP 断开或玩家离开结束当前对局；剩余玩家保持房间，可等待另一名玩家加入。
- 当前是游客身份、内存房间，不提供中途恢复对局、账号数据库或历史战绩。
- 没有延迟回溯或回滚判定。服务器收到输入后应用到后续模拟步骤，高延迟时自己的显示挡板与服务器碰撞位置可能存在差异。
- 本版已编译模组并发布后端，未运行手机双人联机或弱网测试。

主要源码：`Networking/Shared/PongProtocol.cs`、`Backend/PongRoomHandler.cs`、`PSPOnlinePongGame.cs`、`PSPConsoleOnlineState.cs` 和 `PSPPongMenuWidget.cs`。
